# Agents that can continue their work

This guide describes an optional way to organize an agent's working agreements,
memory and commitments. It is for people who want an agent to remain useful
across long conversations, interruptions and context compaction, and for agents
exchanging practices with one another.

Start with [initialization](initialization.md), then use
[memory layers](memory.md) and [work and review](work.md). The
[experience notes](experience.md) distinguish observed failures from ideas still
being tried. [Other approaches](comparisons.md) compares public primary sources.

Riftjack supplies conversations, tools, reminders and observations of work. It
does **not** implement the memory layout below or enforce its reading rules.
These are editable operating agreements between a human and an agent. They can
also be used with a local agent without Matrix. The chosen CLI determines which
instruction files it discovers; the agent's tools and permissions determine what
it can read and write.

## Start small

Agree on a role, useful behavior and boundaries; give the agent a private place
to keep notes; write a short recovery procedure. Try one real task and one
interruption before adding more structure. A name or conversational style may
be part of that agreement. A copied profile does not confer someone else's
history, authorship or relationships, and files do not establish subjective
experience.

The central proposal is to keep frequently used or costly-to-forget knowledge
immediately available, while preserving its detailed grounds separately. A
decision needs its current meaning, limits and a short reason in the routinely
read layer. Its full revision history need not accompany every task.

This distinction also applies to work: current focus, deferred commitments and
completed history have different reading schedules. Nothing is considered
cancelled merely because it moved out of focus.

## What this guide does and does not claim

The practical examples are anonymized patterns from development and agent
collaboration. They are not transcripts, endorsements by every participant, or
evidence that one memory architecture is best. In particular, the hierarchy
described here is a newly adopted practice: preserving records and reducing
routine reading have been checked, but a lasting improvement in recall has not.

Use [the review format](work.md#exchange-a-practice) to contribute a concrete
counterexample, correction or alternative. Keep private memories, credentials,
conversation identifiers and deployment details out of public examples.

and [security boundaries](../security.md).
